# Agent Note: 上屏后联想与组字状态分离

Status: proposed

## Problem

#9433 要求选中「吃」后仍能在候选栏选择「饭」「东西」等后续内容。现有整句候选只重排正在输入的拼音，空闲会话没有下一词生产者；运行时又把非空候选视为组字，直接填入候选会造成空格误选、失焦误提交和数字键被截走。

## Proposal

新增独立的 `next_word_prediction` 偏好，默认关闭，Android 在「表达 → 智能」提供「上屏后联想」。共享引擎拥有联想状态与候选，运行时保留正常的带代次候选选择，并明确区分联想与组字。只有显式选择能提交联想；新输入、标点、空格、回车、删除、取消、失焦、外部光标移动、切换布局或模式清除建议。

数据源是现有拼音词库的同字同音前缀续词，以及学习已启用时的个人相邻词记录。拼音查询在 `key` 前缀索引范围内筛选汉字前缀，再截取未上屏部分，最多返回八行；不开新模型、不联网、不全库反查。个人查询合并已落盘和待刷新的同一批转移，遵守 `writer → pending → model` 锁顺序，读取不创建 journal。密码或私密输入继续使用宿主已有的隐私门禁，停用学习时不读取个人词序。

首轮接入覆盖 Android 全拼、双拼及触屏组码布局。底层能力共享，但其他宿主没有完成交互验收前不启用该选项。普通空格仍插入空格，回车仍执行编辑器动作，数字仍输入或开始九键组字，失焦不会提交建议。

## Existing decisions

- [整句候选文案](../../implemented/bug-fix/2026-10-23-android-sentence-candidate-wording.md)：部分重叠，保留原设置的含义，本篇新增独立能力并互链。
- [九键个人排序](../../implemented/feature/2026-10-09-nine-key-initials-personal-ranking.md)：只约束组字候选的排序，不承担空闲建议；继续复用同一份个人 journal。
- 备份习惯相关笔记说明既有表的恢复方式，与本次只读查询无决策冲突；不改变存储格式。

## Alternatives considered

- **独立可枚举预测模型**：可以提供更广的跨词语义覆盖，但现有内置二元、三元模型只有哈希与分数，无法枚举词面；引入新模型还需要来源、许可证、资源分发与内存预算。现有词库续词和个人词序能提供真实建议，先复用这些已部署的数据。
- **把建议放进普通组字**：能复用所有候选交互，但会让空格、回车和失焦把用户没有输入的建议当成待提交文字，必须独立标记状态。
- **只修改设置文案**：最小且不改变输入行为，已由前篇完成，但无法满足 #9433 的实际需求。

## Acceptance criteria

合成词库中选中「吃」后出现「饭」「东西」，不出现同音不同字前缀。学习的跨词转移能在刷新前后产生相同排序。关闭开关时行为不变；全拼、双拼、九键和十四键都能选取建议。连续选择、输入新字母或数字、空格、回车、删除、标点、光标移动、失焦、偏好切换与过期候选选择均有回归；候选列表不引起组字生命周期事件。共享 Rust、宿主接口与 Android 设备验证各自报告实际覆盖，完整 quick 门禁通过后提交。

## Risks

词库续词不等于通用语言模型，冷启动建议的范围受现有短语覆盖限制；不虚构命中。个人查询必须排除隐私输入，并避免与后台刷新重复计数。Android 自己上屏引起的延迟选区回报不能清除新建议，真正的外部选区变化必须清除。系统盘不足 50 GiB，不新建完整本机构建树，Rust 验证使用远端 Linux。
