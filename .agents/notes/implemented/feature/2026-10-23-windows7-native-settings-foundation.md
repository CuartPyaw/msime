# Agent Note: Windows 7 原生设置窗口的持久化、快捷键、工具栏与维护

Status: implemented

## Problem

现有 Windows 设置使用 WinUI 3，无法作为 Win7 设置入口。兼容窗口必须使用相同配置、默认值和版本能力过滤，并且不能在保存少数字段时抹掉其他页面、令牌或另一窗口的修改。完整页面适配期间也不能把普通 Windows 的设置入口切到未完成的窗口。

## Decision

`settings/win7` 使用 Win32 标准控件和系统字体、颜色、DPI，复用不依赖 WinRT 的页面模型与同一个 Rust Host API。独立目标 `msime-client-settings-win7` 目前提供快捷键的按键设置与按键速查，以及悬浮工具栏的显示、按钮与尺寸控件；维护与诊断页提供服务与 TSF 日志开关、服务重启、目录打开和设置文件导入导出。只有同时含中文与日语方案的版本显示日语切换控件，不提供手写的版本不画手写按钮开关；不添加未实现页面的占位入口。工具栏图形预览和颜色页跳转尚未完成。普通构建、启动器、安装包及出厂默认值保持现状。

`PreferencesStore` 保留完整快照，按明确存在的路径替换字段，带原修订号调用 Rust 的比较并交换保存。默认值、配置格式、字段校验和磁盘提交均由 Rust 负责。切换中英文的三个互斥布尔值在一次保存中修改；不改动无关字段。工具栏尺寸复用 `FloatingToolbarSizeModel.h`，一次保存缩放与字体尺寸；已有自定义值照实显示，进入页面不归一化存储。当前 C ABI 没有冲突错误码，适配器识别其实际描述 `preferences changed; reload before saving`，并以集成测试约束这一边界。

所有配置和运行时选项文件读写在串行工作线程执行；界面等待时禁用编辑控件，不累积整份旧快照。保存失败后重新读取实际状态并提示，既处理并发冲突，也处理可能已经落盘后清理失败的情况，不自动重试覆盖。关闭时完成已受理的保存并等待线程退出；完成消息不传堆指针，不把结果发给已销毁窗口。状态目录优先级与现代窗口一致，读取运行时选项有大小上限。

设置文件通过现有 Rust 导出与导入接口处理，复用 `SettingsDocumentFile.h` 的大小、UTF-8 和文件写入约束。导入带当前修订号，不覆盖并发修改；服务配置与密钥、诊断日志、使用统计和剪贴板历史开关按共享规则保留。文件选择在窗口的 STA 使用从 Vista 起支持的 `IFileDialog`，文件内容的读写与导入仍在串行工作线程执行。服务重启复用当前 edition 的 Aux 管道，仅提示是否已发送请求；目录打开优先实际日志子目录，不存在则打开数据目录。

独立 CMake 目标使用同架构、同源核心导入库；开发时可指定既有原生依赖前缀，CI 使用此目录的最小 vcpkg 清单，仅安装现有锁定版本的 JSON 依赖。`windows-settings` 在构建同源普通核心后构建和运行此目标，现代 WinUI 页面验收继续保留。CI 覆盖控件和存储，专用 Win7 核心、运行库与实机兼容性继续单独验证。

## Testing

Windows 11 上 MSVC `/W4 /WX` 的 x64 与 x86 构建均通过。真实同源 Win7 Rust 核心的集成测试覆盖修订号冲突、无效字段与类型拒绝、合成令牌与无关字段保留、窗口组合框和复选框通知经工作线程落盘、外部更新后界面刷新，以及关闭窗口时完成已受理保存。按键速查保留 Windows 固定支持的 Tab 和 Page Up/Down，不因对应共享偏好关闭而错误隐藏。工具栏测试还覆盖标准尺寸的单次提交、自定义尺寸仅展示不改写和按钮开关经实际控件保存。维护页测试覆盖两种日志开关、真实设置文件导出后经控件修改并导入恢复、保留合成令牌和本机日志状态，以及取消选择时不写入。文件选择器通过构造参数注入合成路径，按钮通知、工作线程、文件读写与 Rust 保存仍走正式路径；不把这项集成测试计作系统文件对话框的桌面验收。另在 Windows 11 交互桌面使用默认设置程序实际打开并取消导出、导入的 `IFileDialog`，取消后无导出或导入；独立验收脚本为 `tests/tools/windows7_settings.ps1`，尚未在 Win7 SP1 执行。最小 vcpkg 清单的安装、CMake 配置、编译与测试已在远端复现通过；workflow 经 `actionlint` 检查通过，尚未在 GitHub Actions 上运行。

最终应用的已知阻断导入检查均通过。该检查没有穷举所有 Win7 导出，也没有验证 VC 运行库、完整产品或真实 Win7 UI；不能据此声称完整 Win7 支持。

## Alternatives considered

- **用 UI Automation 贯通系统文件对话框。** 可以覆盖实际选择行为，但保存与打开的控件模型、自动补全及交互桌面状态都会影响驱动，服务会话中的不确定性还会掩盖应用的文件读写断言。集成测试在文件选择边界注入路径，系统对话框单独做桌面验收，不因驱动失败就跳过实际配置验证。

- **冻结旧 WebView2 并复用共享 React 设置。** 可减少界面适配量，但依赖停止维护的旧引擎，前端能力和当前插件也没有完整兼容保证。原生兼容窗口可以直接复用共享 Rust 业务接口与既有纯页面模型。
- **在 UI 线程直接调用配置 API。** 实现更少，但目录、文件与锁等待会阻塞窗口；串行工作线程维护一份实际读取的快照，明确保存与关闭的顺序。
- **冲突后自动合并并重试。** 可以减少用户重做，但多字段操作存在业务关系，重试可能覆盖另一窗口刚做出的选择。这里刷新并提示，由用户决定下一次修改。

## Consequences

兼容设置有了可执行、可持续测试的存储与原生窗口基础，现代入口仍保持完整功能。代价是维护第二种 UI 承载，当前快捷键页、工具栏设置控件和维护与诊断操作可用，工具栏预览与跳转仍未完成；仍需逐页复用共享模型、覆盖所有操作，并在 Win7 SP1 和现代 Windows 上进行桌面与安装验收。
