# Agent Note: 原生兼容设置窗口的持久化、快捷键与工具栏控件

Status: implemented

## Problem

现有 Windows 设置使用 WinUI 3，无法作为 Win7 设置入口。兼容窗口必须使用相同配置、默认值和版本能力过滤，并且不能在保存少数字段时抹掉其他页面、令牌或另一窗口的修改。完整页面适配期间也不能把普通 Windows 的设置入口切到未完成的窗口。

## Decision

`settings/legacy` 使用 Win32 标准控件和系统字体、颜色、DPI，复用不依赖 WinRT 的页面模型与同一个 Rust Host API。独立目标 `msime-client-settings-legacy` 目前提供快捷键的按键设置与按键速查，以及悬浮工具栏的显示、按钮与尺寸控件。只有同时含中文与日语方案的版本显示日语切换控件，不提供手写的版本不画手写按钮开关；不添加未实现页面的占位入口。工具栏图形预览和颜色页跳转尚未完成。普通构建、启动器、安装包及出厂默认值保持现状。

`PreferencesStore` 保留完整快照，按明确存在的路径替换字段，带原修订号调用 Rust 的比较并交换保存。默认值、配置格式、字段校验和磁盘提交均由 Rust 负责。切换中英文的三个互斥布尔值在一次保存中修改；不改动无关字段。工具栏尺寸复用 `FloatingToolbarSizeModel.h`，一次保存缩放与字体尺寸；已有自定义值照实显示，进入页面不归一化存储。当前 C ABI 没有冲突错误码，适配器识别其实际描述 `preferences changed; reload before saving`，并以集成测试约束这一边界。

所有配置和运行时选项文件读写在串行工作线程执行；界面等待时禁用编辑控件，不累积整份旧快照。保存失败后重新读取实际状态并提示，既处理并发冲突，也处理可能已经落盘后清理失败的情况，不自动重试覆盖。关闭时完成已受理的保存并等待线程退出；完成消息不传堆指针，不把结果发给已销毁窗口。状态目录优先级与现代窗口一致，读取运行时选项有大小上限。

独立 CMake 目标使用同架构、同源核心导入库；开发时可指定既有原生依赖前缀，CI 使用此目录的最小 vcpkg 清单，仅安装现有锁定版本的 JSON 依赖。`windows-settings` 在构建同源普通核心后构建和运行此目标，现代 WinUI 页面验收继续保留。CI 覆盖控件和存储，专用 Win7 核心、运行库与实机兼容性继续单独验证。

## Testing

Windows 11 上 MSVC `/W4 /WX` 的 x64 与 x86 构建均通过。真实同源 Win7 Rust 核心的集成测试覆盖修订号冲突、无效字段与类型拒绝、合成令牌与无关字段保留、窗口组合框和复选框通知经工作线程落盘、外部更新后界面刷新，以及关闭窗口时完成已受理保存。按键速查保留 Windows 固定支持的 Tab 和 Page Up/Down，不因对应共享偏好关闭而错误隐藏。工具栏测试还覆盖标准尺寸的单次提交、自定义尺寸仅展示不改写和按钮开关经实际控件保存。最小 vcpkg 清单的安装、CMake 配置、编译与测试已在远端复现通过；workflow 经 `actionlint` 检查通过，尚未在 GitHub Actions 上运行。

最终应用的已知阻断导入检查均通过，x64 与 x86 分别检查 225 与 221 个具名导入。该检查没有穷举所有 Win7 导出，也没有验证 VC 运行库、完整产品或真实 Win7 UI；不能据此声称完整 Win7 支持。

## Alternatives considered

- **冻结旧 WebView2 并复用共享 React 设置。** 可减少界面适配量，但依赖停止维护的旧引擎，前端能力和当前插件也没有完整兼容保证。原生兼容窗口可以直接复用共享 Rust 业务接口与既有纯页面模型。
- **在 UI 线程直接调用配置 API。** 实现更少，但目录、文件与锁等待会阻塞窗口；串行工作线程维护一份实际读取的快照，明确保存与关闭的顺序。
- **冲突后自动合并并重试。** 可以减少用户重做，但多字段操作存在业务关系，重试可能覆盖另一窗口刚做出的选择。这里刷新并提示，由用户决定下一次修改。

## Consequences

兼容设置有了可执行、可持续测试的存储与原生窗口基础，现代入口仍保持完整功能。代价是维护第二种 UI 承载，当前快捷键页和工具栏设置控件可用，工具栏预览与跳转仍未完成；仍需逐页复用共享模型、覆盖所有操作，并在 Win7 SP1 和现代 Windows 上进行桌面与安装验收。
