# Agent Note: Android 文本编辑面板固定网格与七键排序

Status: implemented

## Problem

#9503 的文本编辑面板右列有七个操作但只能同时显示四个，数字键盘、空格和换行需要滚动才能发现。需求图将方向键放在中央十字，两侧分布功能键，四个角落留空，并允许调整七个侧边键的位置。

## Decision

面板使用四行五列的固定网格，中央为上、左、选择、右、下，底部为文档开头和结尾。侧边七个位置从左列上到下、再到右列前三行编号；换行固定在右下角。默认顺序为复制、粘贴、全选、剪切、空格、数字键盘、退格。空白格使用面板底色，拦住穿透但不提供动作。

七键顺序保存在共享偏好 `touch_text_edit_button_order`，默认值、七个稳定动作身份及完整排列校验归 `client-core`；经现有偏好 C ABI/JNI 读写，Java 只画位置、提交排序草稿和适配编辑器动作。Android 原生「键盘 → 布局」提供排序入口，保存前可上下移动、重置或取消。其他宿主保留该偏好。

## Related notes audit

[原文本编辑面板](../../implemented/feature/2026-10-08-android-text-edit-panel.md)持有编辑器动作和旧滚动布局，本篇只替代布局及滚动访问的决定；[最近复制预览](../../implemented/feature/2026-10-15-android-recent-copy-in-text-edit.md)继续持有预览和返回行为。[工具栏顺序](../../implemented/feature/2026-10-15-android-toolbar-order.md)提供排序交互参照，但工具栏与文本编辑键位分别持久化。

## Alternatives considered

- 保持右列滚动：原按键无需缩小且改动少，但隐藏三个功能的可发现性问题仍然存在。
- 把顺序另存 Android 本地设置：可以复用工具栏排序实现，但新设置的默认值和校验会继续分散在 Java，违背共享偏好规则归 Rust 的边界，因此使用现有共享偏好存储。

## Consequences

十五个操作同屏显示，中央方向键保持十字，四个空白角不绘制按钮。七个侧边功能的顺序跨设置页与键盘进程持久化，重置使用共享 Rust 默认值。所有动作继续交给原有编辑器适配，最近复制预览与返回键不变。

代价是左右方向键由跨三行变成一格，五列也比原四列更窄。横屏、单手和浮动模式需要检查可用空间；设置面板采用已有的上下移动交互，保存前仅修改草稿。默认值和校验依赖配套的 Rust 原生库，不能拿旧 JNI 配新 Java 包声称整体验证。

## Verification

- Rust 两项回归通过：完整排列保存回读、恢复默认和旧文档缺字段默认值；缺项、重复和未知动作被拒绝，失败不推进修订号。
- `check-host.sh` 初轮发现新增入口缺搜索关键词，补齐后通过 258 项 JVM smoke、225 份设备源码编译和 JNI/Java/API/资源契约。固定布局回归检查全部动作、四角留白、默认和反向顺序以及原编辑器事件。
- `TextEditRecentClipboardDeviceSmoke` 增加真实设置页的取消、保存、重置、页面重开与键盘进程读取排序，并把原滚动测试改为所有快捷键完整可见和真实点击。新增断言尚未在设备执行。
- Gradle `:app:compileFullReleaseJavaWithJavac`、`client-core` 严格 Clippy、Rust 格式、共享偏好字段一致性和 `pnpm build`（包含 TypeScript 检查）通过。
- macOS 偏好覆盖检查先因缺少新字段的适用范围声明而失败；补充「仅 Android 原生文本编辑面板读取，共享 macOS 设置页不显示入口」后通过，扫描器四项回归也通过。
- 本地 quick 已通过 Windows 可移植测试、契约、笔记、Rust workspace、Android 与 WASM 目标检查；随后因本机只剩约 7 GiB、远端系统盘约 24 GiB，主动停止于后续原生构建之前，退出 143，不能记为完整通过。Rust 阶段复用主工作区现有标准 `target/` 缓存，未新增完整依赖构建树，也未启动原生库与专用 AVD 完整构建。
- API 28/35 原生包、设置和编辑器专项、横屏/单手/浮动触控尺寸仍需验收。设备缺口关闭前保持草稿，不能据 JVM 或编译检查声称设备通过。
