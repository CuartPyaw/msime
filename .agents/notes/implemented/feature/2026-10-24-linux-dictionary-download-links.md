# Agent Note: Linux 首次配置提供手动下载词库链接

Status: implemented

## Problem

#9529 报告首次配置的镜像下载超时，希望取得链接后使用其他工具下载。安装器已有 `--resources` 和默认用户资源目录的校验入口，但首次配置页和终端没有可直接使用的下载清单。

## Decision

安装器从当前安装包的词库锁导出只读清单，包含文件名、原地址、当前镜像地址、大小、SHA-256 和默认保存目录。`--list-downloads` 打印人工可读说明，配合 `--json` 供设置应用读取；此入口在状态目录检查之前返回，不联网、不准备目录、不注册输入法。首次配置页按需展示清单，复制链接或保存目录，提示按原名备齐后关闭自动下载并继续配置。原有准备和完整性校验保持唯一入口。

历史检索：[下载客户端身份](../../implemented/bug-fix/2026-10-15-linux-download-user-agent.md)负责镜像请求头，部分相关，保留并互链；[首次配置与面板交互](../../implemented/feature/2026-10-20-linux-panels-and-setup-mac-parity.md)负责图形安装流程，部分相关，保留并互链。共享安装器的锁与原子发布笔记不改变。

## Alternatives considered

- **只在 README 固定一组发布链接**：无需新增接口，用户立即可复制；但并排版本与旧安装包需要不同清单，词库更新后文档里的链接可能与本机校验锁不一致。
- **延长超时或改用另一套下载器**：可以改善部分网络的自动下载，但用户明确需要交给自己的工具，换下载器仍不能提供这个选择。

## Verification

真实安装布局的 CLI 回归在固定基点因不识别 `--list-downloads` 失败，改后通过；覆盖 full/五笔版本、已有状态、禁网与禁止启动子进程、镜像开关、缺少地址和锁文件、无目录写入及原 SHA-256 校验拒绝。首次配置页 20 项测试和 TypeScript 类型检查通过；新增用例覆盖按需读取与缓存、复制原地址/镜像/目录、失败重试和继续旧配置流程。

安装器定位、注册、下载上限、HTTP 升级与六版本渲染回归通过；前端构建、定向 lint/格式和笔记校验通过。完整 `bash scripts/verify-local.sh --quick` 在 Windows 复用已有标准缓存执行，退出 1：18 个失败阶段均在前一轮的 19 项集合内，30 个可移植失败文件与前一轮相同；原生 Windows 全量工程未配置而跳过，不能把少一个失败当成修复。Linux 两项因无 Docker 跳过；真正 Linux 设置应用的 Rust 编译与单测，以及原生首次配置界面验收仍缺。脚本与 jsdom 结果不能替代这些验证。

## Consequences

用户可用自己的下载工具取回与本机锁一致的文件；设置应用增加一次按需的短生命周期安装器调用，沿用有界输出和超时清理。旧脚本不支持清单时图形页显示错误并保持原有配置可用；清单按安装包取值，不承诺镜像或原地址在每个网络可达。只提供外部下载路径，不引入另一套下载或资源发布逻辑。
