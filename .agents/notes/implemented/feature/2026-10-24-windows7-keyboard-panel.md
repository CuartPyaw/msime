# Agent Note: Windows 7 原生屏幕键盘的按键与目标窗口

Status: implemented

## Problem

共享屏幕键盘依赖 Tauri，而 Windows 7 需要不依赖 WebView 的原生承载。键盘与文字面板不同，应向用户每次点击时正在使用的编辑器发键，不能一直恢复打开面板时的旧窗口，也不能把一次失败的输入重放到其他编辑器。

## Decision

使用不激活的 Win32 窗口和标准按键控件，提供完整 PC 按键、功能区、数字小键盘、九键与九键双拼键面。双拼提示从共享 C ABI 读取实际方案，不另存键位表。布局与修饰键属于面板状态，不能在打开时重写出厂偏好。设置页提供高度、两种间距、顶部语音入口、打开键盘与手写、主题跳转和可拖动预览；只保存明确编辑字段。显式恢复默认仅删除共享页对应的五个键，经同一个修订比较接口保存，让共享层给出默认值；删除权限不能泛化到其他字段。

每次普通按键释放时捕获当前外部窗口，发送前再次核对；一次 `SendInput` 提交按下修饰键、主键及反序释放，拒绝无前台或面板自身。标准按钮仅在同一键内松开触发，移出取消，长按不重复。Ctrl／Alt／Win 保持面板粘滞选择，Shift 使用一次后清除，字母使用 Caps Lock 与 Shift 的异或；组字提交键遵守现代面板的修饰键排除策略。失败可能部分发送，必须提示且不自动重试。所有发送保持窗口消息顺序，不创建可越过旧焦点的异步发送队列。

## Alternatives considered

- **直接运行系统 osk.exe。** 它本来支持 Windows 7，维护成本小；但不包含本产品的九键双拼键面、主题和语音入口，因此保留产品自己的原生面板。
- **异步工作线程逐键发送。** 可让界面不等待，但必须额外维护有界队列与目标代次，而本地 `SendInput` 本身是短时系统调用，因此在 UI 线程按消息顺序一次提交完整序列。

## Consequences

实际 HWND 测试覆盖完整键面、修饰键、按下与松开、移出取消、前台目标变化、同步发送、共享双拼提示以及配置只读；设置页测试覆盖仅保存编辑字段、修订冲突和显式恢复默认。完整版本 x64／x86，以及日语和五笔 x64 的设置窗口各 12 套测试通过；x64／x86 面板各 7 套通过，已知阻断导入检查分别覆盖面板 280／275 项，设置程序 x64 358／x86 352 项。两架构的云词库面板使用同一会话单例，整套测试必须顺序运行；同时启动会按设计拒绝第二个实例。

macmini 的全仓 quick（20261024-080021）通过。完整自定义皮肤渲染与预览仍需补齐，基础 GDI 键面不能代表全部皮肤能力。真实目标应用的键盘布局、UIPI、TSF 与系统快捷键处理不能用注入接收器证明。Win7 显示与真实输入仍需系统入口验收；pve9／100 为 Win7 SP1 x64，控制台登录等待维护者补充，连接成功不计为产品验收。
