# Agent Note: 短表情候选锚定使用线性扫描

Status: implemented

## Problem

混排表情或颜文字带有关键词时，锚定逻辑会先为当前候选词建立并排序索引 `Vec`。常见短候选列表只包含少量行，却仍承担一次临时堆分配。

## Decision

候选列表不超过 64 行时直接线性查找关键词对应的首个候选位置，不创建索引缓冲；较长列表继续使用排序索引和二分查找，避免大量候选下重复扫描。锚点顺序、重复候选的首次位置和未锚定行的截断规则保持不变。

## Alternatives considered

- **始终建立排序索引**：大列表查找效率好，但短列表每次表情查询都会多一次堆分配。
- **所有列表都线性扫描**：可以移除索引分配，但大列表和多关键词组合会重复扫描候选，拖慢常见长查询。
- **为索引使用固定大数组**：可避免堆分配，但会在每次调用栈上占用与候选上限相关的空间。

## Verification

新增短列表分配回归测试；旧实现产生 1 次临时分配并失败，线性路径降为 0 次。通过 `ime::queries` 测试，随后继续运行完整引擎测试、Clippy、格式检查和 quick 门禁。

## Consequences

短候选表情锚定不再为候选词索引分配堆内存；长列表继续保持排序后二分查找的复杂度，输出顺序和锚定行为不变。
