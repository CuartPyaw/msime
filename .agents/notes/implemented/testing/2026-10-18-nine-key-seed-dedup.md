# Agent Note: 九键种子重复路径在复制前检查

Status: implemented

## Problem

`seeded_paths` 为每条尾段先建立组合路径、复制种子前缀字符串，再调用 `alternatives.contains`。已经存在的路径会立即丢弃这些新存储；没有剩余尾段时还会建立只含一条空路径的外层向量。

## Decision

会话内至多32个前缀音节一次切分到栈上借用槽位；超长纯函数输入保留迭代器回退，不新增输入限制。使用借用的种子前缀音节与尾段音节，逐项比较已有路径；确认不存在后才建立组合向量并复制前缀。尾段仍按现有上限切分，只有空尾段直接提交空 `Path`，不建立临时外层向量。保持种子访问、尾段访问、首次插入和去重的顺序。

## Historical audit

检索了 `seeded_paths`、种子去重、种子物化与重复路径。[种子尾段采用上限](../../implemented/testing/2026-10-17-nine-key-seed-tail-materialization.md)负责限制尾段根页物化为三条，本片在其后避免重复组合；[最终路径缓冲](../../implemented/testing/2026-10-18-nine-key-path-buffer.md)负责普通路径输出复用，不覆盖种子追加的临时组合。两项决定继续保留，无完全吸收的旧笔记。

## Alternatives considered

- 保留拥有路径之后的 `contains`：最容易阅读，能直接使用 `Vec` 相等比较，但每条重复种子都承担组合向量和前缀字符串的临时分配。
- 为种子路径增加哈希集合：密集重复时可以降低线性查找次数，但要构造键或携带借用路径的生命周期，还会引入额外存储；现有有界路径列表可直接比较。
- 让切分函数返回借用路径：还能避免重复尾段本身的字符串分配，但需要携带后继页所有权，扩大已有切分输出契约；本片只消除组合阶段已经确认的浪费。

## Verification

先冻结 `dd0b58ea16` 的完整种子追加函数。完整重复种子的零分配测试在生产代码修改前运行；追加三种网格、两种频度、空/不匹配/重复/完整种子、预填路径与逆序预填路径的逐输出对照，以及重复尾段的分配对照。随后运行引擎、golden、运行时、Clippy、格式、笔记与本地 quick 门禁。局部 release 配对覆盖三种网格、两种频度、六种种子形状和有无预填路径，共72格；每格40对交替先后，旧臂校准至少5 ms，包含追加和新增结果析构。已预填的完整重复种子形状1和5要求新/旧中位比小于0.98，其余控制小于1.05；不据此声称端到端延迟改善。

## Consequences

重复组合无需建立向量和复制前缀，空尾段少一个临时外层向量；新组合仍拥有独立字符串。代价是每个种子多用32个借用槽位的栈空间；超长纯函数调用仍在比较时重新迭代前缀，尾段切分和它已经生成的字符串仍有分配。分配减少不证明设备端延迟或端到端预算改善。

## Rejected first variant

首版直接为每条已有路径重新迭代 `seed.split`，优点是没有前缀暂存和位数分支，分配测试全部通过。但72格 release 配对有15格未达预设预算，预填完整重复路径的中位比最高3.296562；该版拒绝接入。原始记录保留在本机 `nine-key-seed-dedup-paired.log`。第二版对实际会话范围的前缀只切分一次，再分别比较前缀与尾段，保留超长输入回退及原预算。
