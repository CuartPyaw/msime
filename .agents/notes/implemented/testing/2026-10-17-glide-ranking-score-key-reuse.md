# Agent Note: 滑行词典重排复用切分词键

Status: implemented

## Problem

滑行词典重排已经把候选切分存成连续音节范围，但评分阶段仍对每条切分重新执行 `join("'")`，长笔画候选因此反复构造相同的词典键并再次做字符串哈希查找。

## Decision

每条切分在生成时物化一次词典键并随范围保存。查询键仍按原契约收集、去重并按字典序传给权重查询；评分直接借用切分保存的键查 `known`，未知词回退继续按音节键查询。候选排序、权重加成和公开接口保持不变。

## Historical note audit

已检索滑行切分存储、词典键去重、拼音切分和词网格键借用笔记。已有滑行键存储笔记覆盖连续范围和批量查询键物化，不覆盖评分阶段重复 `join`；本笔记记录后续评分路径的复用。

## Alternatives considered

- **继续在评分阶段 `join`**：改动最小，但每条切分每次重排都会重新分配键字符串。
- **仅缓存每条切分的评分值**：能减少一次查表，但仍需先构造词键，也无法复用查询键。
- **跨调用缓存切分键**：输入候选和切分边界变化频繁，缓存会增加失效与常驻内存边界；本次只在一次重排调用内保存。

## Verification

新增回归测试在旧实现上以 119 次分配超过 110 次上限，在新实现上通过；滑行模块 16 项测试、Engine 全量单测、Clippy（`-D warnings`）、Rustfmt 和差异检查通过。

## Consequences

切分阶段多保留一次词键字符串，评分阶段不再重复 `join`；最终查询键仍是独立拥有且字典序排列的 `Vec<String>`，权重查询契约未改变。收益只覆盖滑行词典重排评分路径，不能据此宣称整体输入延迟达标。
