# Agent Note: 固定候选只保留必要的词文本

Status: implemented

## Problem

`InputSession::pin_candidate` 在执行固定操作前无条件克隆完整 `WordItem`。频率排名会重新借用当前候选，固定记录完成后只需要来源和词文本；辅助码、句子边界和其它候选元数据不会跨越这次可变操作。

## Decision

先借用并验证候选，保存来源枚举和词文本，随后调用频率排名；记录 pinyin 固定候选时使用保存的词文本。排名和固定记录的执行顺序保持不变，失败时仍返回原有诊断。

## Alternatives considered

- **继续克隆完整候选行**：逻辑最简单，但固定操作额外复制不会使用的字段。
- **在排名前写入固定记录**：可以继续借用候选，但会改变排名失败时不写固定记录的现有行为。
- **重构排名接口持有候选借用**：会把候选列表借用带入日志写入，影响范围超过固定操作本身。

## Verification

新增不可编辑候选的固定分配回归测试：旧实现会为完整 `WordItem` 克隆产生 2 次分配，优化后固定操作本身为 0 次分配；已有混合五笔固定行为测试、目标测试、完整 `msime-engine` 测试、Clippy、格式检查、笔记校验、差异检查和 quick 门禁覆盖提交。

## Consequences

固定候选不再复制完整 `WordItem`；来源判断、频率排名、个人固定记录、刷新候选和诊断行为保持不变。
