# Agent Note: 固定候选位置扫描跳过无用分配

Status: implemented

## Problem

`apply_fixed_positions` 在普通候选列表不含在线候选时，仍会先把列表拆成保留行和动态行，再重新拼回；没有固定位置记录时还会继续构造临时查找表。常规候选刷新因此产生不必要的临时堆分配。

## Decision

只有列表确实包含在线候选时才执行动态行分区；固定位置和动态行都为空时立即返回。含在线候选或固定位置记录的路径保持原有处理顺序和插入规则。

## Alternatives considered

- **始终分区候选列表**：行为简单，但普通输入的每次刷新都会分配两个临时缓冲。
- **永久缓存动态候选缓冲**：可以复用容量，但会扩大会话状态并增加清空时机，当前收益不需要这种复杂度。
- **只跳过分区而继续构造候选哈希表**：仍会为没有任何位置变更的普通列表分配查找表，因此同时在无固定行、无动态行时提前返回。

## Verification

旧实现的回归测试在两行普通候选上报告 2 次临时分配并失败；优化后为 0 次并通过。完整 `msime-engine` 测试通过（1324 单测、31 golden），Clippy、格式检查、`git diff --check` 和 `bash scripts/verify-local.sh --quick` 均通过。

## Consequences

普通候选刷新不再为动态分区和空固定位置扫描分配临时缓冲；在线候选、固定位置和候选顺序行为保持不变。现有会话分配基线随之下降：光标前缀扩展 395→390，末尾输入 155→152，移动光标 72→70。
