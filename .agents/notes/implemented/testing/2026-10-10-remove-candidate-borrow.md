# Agent Note: 借用待删除候选行

Status: implemented

## Problem

`InputSession::remove_candidate` 在确认候选来源可编辑之前克隆完整 `WordItem`。不可编辑的临时、生成和只读方案候选会直接早退，但仍为行内字符串和句子词列表付出分配成本。

## Decision

从候选列表借用待删除行，先完成来源、单字保护和方案判断；删除写入接口只读取行字段，因此继续沿用同一借用直到刷新候选。删除成功后仍按原流程重建候选，失败诊断和列表状态保持不变。

## Alternatives considered

- **继续克隆完整候选行**：改动最小，但每次拒绝删除不可编辑候选都会复制不会使用的字段。
- **只复制删除所需的字段**：可以避开完整行复制，但仍会为最终早退路径分配字符串，并增加字段生命周期管理。
- **把候选行从列表中移出再写回**：能转移所有权，却会改变候选列表的暂时结构，刷新和失败回滚更复杂。

## Verification

新增不可编辑 `Fallback` 候选的分配回归测试。旧实现先失败并报告 2 次分配，借用行后为 0 次；删除拼音行、删除失败回滚和相关 `removing_` 测试均通过。

## Consequences

不可编辑候选的删除早退不再克隆 `WordItem`；可编辑候选的词库删除、日志诊断、刷新顺序和单字保护规则保持原有行为。
