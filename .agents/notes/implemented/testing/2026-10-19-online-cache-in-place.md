# Agent Note: 在线候选回写直接更新已有缓存页

Status: implemented

## Problem

固定 `4f499433c570ba50414c2fc68c4a060820089a8a` 的全拼在线回写、双拼系列回写和双拼辅助码回写都先通过 `FifoCache::get` 深复制整页，再修改副本并替换原页。每个保留的本地候选因此复制全部字符串和词边界；无效批次也复制后丢弃。批次函数已经保证返回 false 时列表不变，缓存原页没有并行消费者，复制并非保持事务所必需。

## Decision

`FifoCache` 提供基于 `lru::LruCache::peek_mut` 的可变槽借用，保持原 FIFO 年龄。在线回写热命中直接将槽交给现有 `replace_online_candidate_batch`；系列未命中仍建立局部空页，只有成功才插入。辅助码未命中仍返回 false，不补建槽。保留槽键、校验、配额、去重、云席位、AI 顺序、个人模型登记和所有失效语义。外部查询继续深复制结果，已返回快照独立拥有。

命中页保留本地行字段存储，不再因整页 clone 紧缩字段；成功后以 `shrink_to_fit` 收紧外层 Vec，失败保持容量不变。外层缩容可能额外调用一次重分配，避免大批次缩小时持续持有富余槽。原字段自身的既有富余容量不收紧，不声称任意输入的驻留内存下降。缓存槽数及 FIFO 寿命不增加。

## Historical audit

已检索在线批次、缓存回写、共享候选和 `replace_online_candidate_batch`。[已有词去重](../../implemented/testing/2026-10-08-online-batch-existing-dedup.md)与[云候选原地重排](../../implemented/testing/2026-10-09-online-cloud-rehome.md)负责列表内操作；本片管理外层缓存页所有权，部分重叠并互链。[解析按需投影](../../implemented/testing/2026-10-14-quanpin-resolution-cache-projection.md)继续持有槽键与解析行为；其冻结在线回写的历史分配对照需隔离本片收益。[回包借用校验](../../implemented/testing/2026-10-17-online-answer-borrowed-validation.md)在更外层，保留。其它平台在线状态和云剪贴板笔记无关，没有完全吸收或过时提案。

本仓 `FifoCache::insert` 已用 `peek_mut` 保持年龄；[lru 0.18.5 官方文档](https://docs.rs/lru/0.18.5/lru/struct.LruCache.html#method.peek_mut)明确该接口不更新链表顺序。沿用现有依赖及 `Vec::retain`，没有新依赖、unsafe、IO 或宿主行为。

## Alternatives considered

- 全链共享缓存页或候选字段：能覆盖更多按键路径的复制，但需改变会话、学习、缓存失效及独立修改的所有权边界；本片已有同步可变槽足以消除回写副本，不扩大结构。
- 移出页后修改再插回：可以转移所有权，但会更新 FIFO 年龄，且失败时还要恢复原槽；可变借用直接保持现有槽。
- 原地更新保留全部外层富余容量：可以避免缩容重分配，但真实序列测试中，16条本地行经历AI10→AI1及云回写后，新页仍持有6274字节，旧替换页仅4098字节；不采用这个初版。
- 保留副本用于事务：失败隔离直观，但现有批次函数先完成所有校验再修改，false 明确保持原列表，逐字段对照测试覆盖该契约。

真实查询后调用生产回写的集成覆盖显式、自动和手动切分、`nue`别名、非默认`gau`纠错并强制`C:`键；两来源分别注入`AiPending`与`CloudPending`，比较返回值、缓存页完整字段及再查询结果。历史解析投影测试改用固定外层回写壳，只隔离候选页所有权，仍调用当前解析投影核心；首次全量中两项历史测试因本片额外减少分配和收紧外层容量而失败，因此隔离各自收益；原精确分配等式与布局预算不变，首字母展开仍走生产路径。

## Consequences

本地字段的既有富余容量继续存活，成功回写还可能多一次外层缩容，不能把少申请泛化为任意输入的持有字节下降。可变槽不能用 LRU 的 `get_mut`，否则读写会改变淘汰顺序。辅助码一次更新两个独立槽，仍按原顺序分别调用批次函数。失效与输入校验不能移位。

## Paired observation protocol

完整回写入口的观察固定为全拼、双拼系列、单辅助码、反查辅助码、双辅助码共5入口，16/128/512条本地行、AI/云/非法批次，共45形状。先验证字段相等，旧批次从32次起倍增到至少2ms，每形状40对交替先后，输入页与批次在计时外；调用和副本析构均在计时内。普通系统分配器release仅运行ignored计时，保留完整1800对和构建进程监测。该计时仅作观测，不设找绿门槛；采用依据是完整入口的精确克隆成本消除、字段/顺序/失效/FIFO和容量序列门禁，不由局部观测宣称九键16ms达标。

## Initial evidence

旧生产上6项专项运行结果为2通过、4失败：全拼和双拼的分配预算分别在0条本地行时以10≠7、9≠6失败；另外两项在本地字符串指针变化处失败。原地初版6项全部通过。新增持有量约束后，两条序列测试在AI10→AI1时真实失败：旧5172、新6260字节；随后更晚的AI/云序列旧4098、新6274字节。最终版增加成功回写外层缩容，原序列约束通过。恢复计数分配器后的专项复跑为10项通过、2项计时忽略，解析投影5项全通过。[全部30条持有量记录](../../../../docs/measurements/2026-10-19-online-cache-in-place-capacity.csv)中，五入口的六步旧/新字节依次相同：6396/5308、5172/3948、3948/3948、6274/4098、4098/4098、4098/4098。这是合成字段容量紧凑时的结果，不是任意输入的内存上界。

[全部配对](../../../../docs/measurements/2026-10-19-online-cache-in-place.csv)记录批次总纳秒及迭代数；[完整分位数](../../../../docs/measurements/2026-10-19-online-cache-in-place-summary.csv)按每次回写计算旧新p50/p95及配对比值p50/p95，分位数采用线性插值。`variant=0/1/2`分别是AI、云、非法批次。45形状的配对中位比范围为0.000490–0.223453，其中有效AI为0.046120–0.197541，云为0.074379–0.223453，非法批次为0.000490–0.047274。非法批次在校验时直接返回，收益不能等同有效候选更新。
