# Agent Note: 词网格单路径合并跳过候选集合

Status: implemented

## Problem

`472a5f3782` 的九键采样仍有 `merge_lattice_graph` 中候选集合构造及字符串散列成本。本片基线 `61891ad5bd` 保留同一构造。`existing_sentence_set` 按候选加路径合计是否超过 64 决定建表；即使只输出一个句子，也会遍历全部已有候选建立一次性哈希索引。

## Decision

实际路径数为一时使用已有线性查询，最多对候选扫描一次；多路径继续遵守现有 64 条边界。复用生成块与神经块的原选择算法，不改变解码、评分、重复策略、输出字段和容量。默认 `emit` 截断之后判断路径数，神经分支依旧在全部模型评分完成后判断。单路径不会产生候选数乘路径数的无界平方行为。

## Historical audit

[短列表去重](../../implemented/testing/2026-10-08-lattice-merge-dedup.md)部分重叠，本片增加单路径例外，原多路径边界保持；[空输出块](../../implemented/testing/2026-10-10-lattice-empty-block-buffers.md)保持分配时机和非空容量；[无来源跳过集合](../../implemented/testing/2026-10-15-lattice-empty-source-dedup.md)仍在模型评分后处理无来源。历史检索未发现同题否决或待清理提案。

## Alternatives considered

- 始终建立集合：保留原逻辑，但只进行一次成员查询时仍承担整表构建和申请。
- 所有路径均线性扫描：省去索引，但多路径与大量候选组合会形成乘积开销。仅单路径例外具有直接的线性上界。
- 扩大通用候选边界：代码同样小，但要同时选择新阈值并验证多路径工作量。本片采用实际单次查询这一明确条件。
