# Agent Note: Android 与 iOS 的语音入口直接开始听写

Status: implemented

## Problem

Android 工具栏的麦克风按钮打开语音结果面板；iOS 的工具栏和功能菜单同样通往结果交接界面，即使后台听写会话已准备好也不能点一下开始说话。两端聆听面板还把大片正文和空白当成取消目标，Android 只有整句上传显示结束采集按钮。用户要求语音识别直接转成文字上屏，正常流程不再经过结果编辑、发送到键盘或手动插入。

## Decision

Android 工具栏和 iOS 工具栏、功能菜单、读屏语音操作直接进入既有键盘内识别流程。最终转写继续经过原输入位置检查后直接上屏；按住空格仍由松手结束、上滑取消。结果交接只服务于输入位置变化等不能自动插入的情形，iOS 仅在确有待取结果时显示「插入语音文字」。

点按开始的聆听面板提供「说完了」和「取消」，前者只停止采集并等待识别，后者丢弃本次录音；正文和空白不再绑定取消。等待最终结果期间结束按钮禁用。iOS 结束听写后立即显示正在识别，迟到的聆听确认仍按识别中处理，不把界面退回录音状态。

iOS 麦克风仍由主 App 持有；后台会话未开或已过期时直接进入会话开启页，返回后重新开始听写。识别服务、润色开关和出厂默认值沿用用户当前选择。

## Alternatives considered

- 仅修改入口文案：可以减少用户误解，但点麦克风仍不能直接录音，且流式面板缺少明确结束操作，因此修正入口路由并统一结束与取消。

## Verification

Android 主机门禁通过，包含 266 个 JVM 冒烟和 240 个设备套件源文件编译。原生宿主设备回归及 iOS 模拟器测试继续进行。

## Consequences

正常语音输入从开始、结束到文字上屏不需要打开结果面板。目标变化时仍保留显式交接，避免将迟到结果写入其他输入框；没有新增文件格式或真实语音日志。
