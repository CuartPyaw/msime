# Agent Note: Windows 日语切回中文后立即发布方案

Status: implemented

## Problem

Windows 的 `Ctrl+Shift+J` 日中切换先在独立工作线程写入共享偏好，再由 `PreferenceMonitor` 每 250 毫秒轮询并发布给输入会话。用户从日语切回中文或英文后马上继续输入时，当前会话仍可能沿用日语方案，于是新字符继续变成假名。方案文件已经写成功，但生效时序落后于用户的下一次按键。

## Decision

日语切换工作线程成功写入方案后，立即唤醒 Windows 的 `PreferenceMonitor`；监视器仍负责读取带版本的完整快照、排入输入队列并按原有顺序发布，唤醒只缩短等待时间，不绕过版本检查或在工作线程直接改 Engine。`PreferenceMonitor::wake` 只发送条件变量通知，不等待发布，也不改变停止状态；服务器在构造完成后注入唤醒回调，构造期间若尚未就绪则继续依靠原有轮询。

## Alternatives considered

- **让切换工作线程直接修改活动会话**：需要把完整偏好快照和焦点租约跨线程传回输入队列，容易绕过已有的 revision、组字延迟和会话失效检查，因此不采用。
- **把轮询间隔永久缩短**：会增加无变化时的磁盘读取和锁竞争，仍不能表达“写入完成后立即检查”，因此不采用。

## Consequences

成功切换后的偏好会在下一次输入前尽快进入既有发布队列，日语组字中的延迟应用规则保持不变；没有发生切换时监视器行为和轮询频率不变。唤醒本身是最佳努力通知，若服务器正在停止或输入队列繁忙，原有监视器仍会按既定重试与错误状态工作。

验证覆盖偏好监视器的显式唤醒发布回归；Windows 原生构建与生产 TIP/Server 联调由 CI 执行。
