# Agent Note: iOS 九键切英文保持键盘总高

Status: implemented

## Problem

手机九键中文使用 52pt 键帽，切到英文后显示 26 键字母行。26 键为了避免键帽又高又细改成 44pt，并在竖屏增加排间距，但高度公式只按收紧后的键区相加，导致切换英文时键盘整体少 20pt，底行和输入框一起跳动。

## Decision

手机竖屏英文 26 键继续使用 44pt 键帽和存储排间距之外的 4pt 留白；键盘高度按九键的 52pt 键区基准计算，省下的 20pt 放在字母键区上下各 10pt。这样字母键仍然较矮、排间距仍然较大，九键中文与英文的 `keyboardHeight` 相同。横屏不增加这 4pt 额外排间距，两个布局沿用相同的横屏高度。

这条约束属于 iOS 宿主的布局契约，`KeyboardFormFactor.keyboardHeight` 负责外框高度，`KeyboardViewController` 负责把补回的空间作为 `keyColumn` 内边距留出；切换布局不能靠改变键帽高度来填满外框。

## Alternatives considered

- 把英文键帽恢复为 52pt：可以直接保持总高，但撤销了用户反馈要求的较矮 26 键，键面又会显得高而窄。
- 只把 26 键的总高度设回九键高度：会让 Auto Layout 把额外空间分给各排，实际键帽再次变高，且行距与测试期望不一致。
- 把三处排间距都继续扩大来填满 20pt：会把默认 11pt 排间距推到约 18pt，破坏当前已调好的垂直节奏；保留排间距并使用上下内边距更稳定。

## Consequences

九键与英文切换时系统键盘外框不再跳高或跳低，英文按键高度和排距保持现有视觉设定。字母层上下各多出 10pt 的留白，键区总高度与九键一致；横屏额外排间距收回，避免英文高度比九键多出一段。回归测试覆盖纯几何公式、实际 26 键高度和九键切英文的约束高度。
