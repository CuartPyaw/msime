# Agent Note: Android 设置搜索的关键词表由冒烟逐页核对

Status: implemented

## Problem

#6132：Android 0.3.1 在设置首页搜「浮动」显示「没有匹配的设置」，而键盘页「布局」组里就有「浮动键盘」开关。

设置首页的搜索（`KeyboardFragment.applySearch`）只看两样：首页各行的标题与当前值，以及 `PageId` 每页的标题和手写的关键词表（`PageId#matches`）。详情页里的行不会自己进索引。`PageId.KEYBOARD_OPTIONS` 的关键词停在键盘页早期的样子，之后加进布局组的「浮动键盘」（#5621）、「横屏分离式键盘」「键盘底栏」「九键左侧符号」「数字键盘顺序」，按键反馈组的「按键动画」，手势组的「九键滑动输入数字」都没补进去。逐页对过之后，表达页的「候选带 emoji」「候选带颜文字」、输入页的「只出单字」和韩语 / 越南语 / 藏语、词库页的「背单词」「云词库」、隐私页的「隐私政策」、开发者页、关于页和帮助页各一行也是同样的情况。

## Decision

- 上面这些行标题补进各自 `PageId` 的关键词；键盘页工具栏的「皮肤」按钮也补上，和同组已在表里的表情、常用语、剪贴板、输入方式一致。隐私页「隐私模式」那一组只有说明没有开关，也作为关键词加进去，搜它能找到说明。
- 新增 `platforms/android/tests/home/SettingsSearchIndexSmoke.java`，由 `check-host.sh` 自动发现运行。它读 `PageId.java` 源码取出每页的标题和关键词，再读对应页面类，把 `GroupCard` 的 `toggle` / `nav` / `slider` 以及开发者页 `uploadToggle` 的字面量标题逐个按 `PageId#matches` 的规则核对；标题来自其他表（`InputFeatureToggle`、输入页的语言表、键盘页的工具栏按钮表）的行在冒烟里逐条列出。按钮行和值行不要求进索引，标题等于另一个可搜索页面标题的导航行视为去那一页的入口。
- 冒烟独立数一遍 `PageId` 的项数，并要求至少核对到 50 行，正则失配时直接失败，而不是静悄悄地少查。

## Alternatives considered

- **让搜索直接扫页面构建出来的行** — 不用维护关键词表，页面加行即可被搜到。但详情页是按需建的 Fragment，很多页面要先读存储（`HostTask`）才画得出行，在首页搜索时把十几个页面全部建一遍代价太大；而且关键词表里还有选项值和简称（「下滑」「上滑」「单列」「双列」「最近复制」），行标题替代不了它们。
- **把关键词提到页面类里的静态常量，由页面和 `PageId` 共用** — 能在编译期保证一致，但页面里的行标题散在条件分支里（只在某些版本出现的九键行、只在有管理界面时出现的「更多」组），要把每个页面的构建代码改成先声明再使用，改动面远大于这个缺陷；`PageId` 按类名注册页面、刻意不引用页面类，也会被打破。
- **在冒烟里直接调用 `PageId`** — 语义最准。但 `PageId` 引用 androidx 注解，check-host 的 JVM 编译只有 android.jar，进不来；所以照 `AndroidLocalSettingsSmoke` 读 Rust 源码的做法读 Java 源码，`matches` 的规则在冒烟里照抄一份。

## Consequences

- **收益**：搜「浮动」能找到键盘页，结果副标题是「浮动键盘」；之后在页面里加了开关、导航或滑块而没补关键词，`check-host.sh` 会列出缺的行并失败。
- **代价**：冒烟按源码正则取行，页面改用别的方法建行、或者行标题改成变量时会漏查；标题来自其他表的那几行要手动维护在冒烟里。`PageId#matches` 的规则改了，冒烟里的副本也要跟着改。
- **未覆盖**：只跑了 `check-host.sh` 的 JVM 冒烟，没有在真机或模拟器上点过搜索结果；其他平台的设置搜索不在这次范围内。
