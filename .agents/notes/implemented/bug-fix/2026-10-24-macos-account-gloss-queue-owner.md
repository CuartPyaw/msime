# Agent Note: macOS 账号候选释义等待页的控制器归属

Status: implemented

## Problem

#9397 报告不同 macOS 应用显示的候选释义不同，报告尚未明确翻译来源，不能把它直接归为词典覆盖或账号服务问题。源码调查发现独立的跨控制器缺陷：输入框各自持有控制器，Swift 后端却共用一个正在发送的请求和一个等待页；旧控制器的迟到取消会无条件删除新控制器已经放入的等待页。

基线 `bcdab74501` 的实际发送、取消方法通过 Foundation 原生夹具运行，合成控制器 A 发送后由 B 接管，A 再取消，断言 B 的等待页仍存在时失败。夹具提取生产方法，只替换输入法外壳和账号后端，不读取用户配置，也不访问账号网络。

## Decision

宿主在主线程用弱引用记录最近实际提交账号请求的控制器。当前焦点控制器有权取消尚未交接的旧等待页，以保留关闭翻译、切换服务或离开输入框的意图；非焦点控制器仅能取消仍属于自己的等待页。非焦点计时器不能向后端提交请求，避免旧页在交接后重新覆盖当前页。取消前先释放归属，避免同步回调中接管的新请求被旧取消的收尾覆盖。

正在发送的请求仍按现有后端规则完成并填充缓存；不修改显示视图代次、词典查找、翻译偏好或公开桥接接口。不据此声明已复现报告人的应用与服务组合。方法级回归同时接入通用契约发现和 macOS CI 的原生构建矩阵，避免 Linux 契约作业的环境跳过成为唯一的 CI 结果。

## Alternatives considered

- 只允许最后提交者取消，能以最少状态挡住迟到取消，但当前焦点退出账号翻译时将无法清理旧控制器尚未交接的等待页；该合成原生断言真实失败。采用焦点退出权限与提交者归属并存，并拒绝失焦后的发送。
- 给 Swift 请求和取消接口都增加所有者参数，可以由后端直接验证归属。但当前账号候选入口仅由这个原生控制器调用，扩展桥接契约增加迁移范围；先在现有唯一入口维护弱引用。

## Verification

基线实际方法首先失败于“迟到的旧控制器不能取消新控制器的等待页”。修复后八项原生回归通过：迟到取消、无请求旁观者、当前所有者取消、同控制器换页、取消回调中接管、新所有者取消、当前焦点退出清理旧页、失焦计时器拒绝发送。方法与弱引用声明取自实际控制器源码，使用合成后端与 Foundation，经 Clang 的 `-Wall -Wextra -Werror -UNDEBUG` 编译运行，不复制被测决策逻辑。

macOS CI 新步骤使用系统 `/usr/bin/python3`，该解释器实际运行八项回归通过；新增 workflow 接线通过 `actionlint`。该接线在远端运行开始后补充，本机单独验证，不将旧运行的 workflow 范围跳过写成接线已受检。`MSIME_CHECK_JOBS=2 bash scripts/run-checks.sh` 完整通过，`pnpm run verify-notes` 的树、格式、归档三项校验通过。完整 `InputController.mm` 与既有 `ShortcutTest.mm` 均通过 Clang 的 C++17、ARC、`-Wall -Wextra -Werror` 语法检查，不依赖已有 Rust 库或新构建树。完整宿主链接、既有控制器运行套件及仓库 quick 尚未完成；方法级原生回归与整文件语法检查不替代这些门禁。报告人的服务来源和实际应用路径仍未现场复验，关联采用 `Refs #9397`。

## Consequences

不再由旧输入框取消或替换新输入框的账号等待页，同时保留当前焦点退出账号翻译时的清理能力。新增一个主线程弱引用，把已有焦点声明提前以供发送入口使用；不改变桥接 ABI、正在发送请求的缓存规则或候选视图代次。源码方法提取回归依赖方法声明与结束格式，重构时需同步；它不创建系统输入法客户端。若账号候选入口新增原生控制器之外的调用方，须重访该归属边界并将所有者传到后端，避免绕过宿主检查。

本机和远端磁盘低于新建构建树的 50 GiB 门槛，完整宿主验证复用已结束的 #9190 构建缓存，只克隆产物并重定位 CMake 缓存路径，不复制其源码。远端 run `20261024-102847` 运行原始 quick，随后运行既有 `shortcut`、`shortcut-translations` 与 `shortcut-vim-mode`；当前尚无终态。11,238 份受控及本任务新增文件双端 SHA-256 一致。当前仅证明独立的共享队列缺陷，不能断言报告人的全部跨应用差异已解决。
