# Agent Note: 移动端统计页统一系统认证规则

Status: implemented

## Problem

Android 已按维护者要求实现「有系统认证就认证，没配置就直接打开」，iOS 和 HarmonyOS 仍在进入统计页时直接加载，三端行为不一致。

## Decision

iOS 使用 `LocalAuthentication.deviceOwnerAuthentication`，支持生物认证和系统密码，仅明确的 `passcodeNotSet` 免认证。HarmonyOS 使用系统 `userAuth` 的 PIN 配置检查和系统认证窗口，仅明确的 `NOT_ENROLLED` 免认证；查询失败、锁定、取消和认证失败均保留重试入口。

认证门放在统计内容挂载之前，未通过时不加载统计、不挂载上传控件。离开页面或应用退到后台撤销授权，丢弃旧认证回调；系统认证窗口短暂抢走焦点不导致重复弹窗。授权只存在于本次页面会话，不持久化。共享 React 页面通过宿主可选能力接入，仅 HarmonyOS 提供，桌面设置不受影响。

检索审计：[Android 无凭据放行](2026-10-25-android-statistics-auth-availability.md)与本篇部分重叠，本篇扩展相同规则到其他移动宿主；[原 Android 认证](../feature/2026-10-25-android-statistics-auth.md)仍负责 Android 接线；剪贴板认证与本次统计页一致性无关。

## Alternatives considered

- 完全移除三端认证：访问路径最短，但不符合维护者最后明确的「有认证就用认证」，因此保留系统认证。
- 所有系统认证错误均视为无凭据：覆盖设备差异容易，但会将已配置凭据的设备故障、取消或锁定当成免认证，因此只认系统明确的未配置状态。

## Consequences

两端配置凭据时先认证，无凭据时直接加载；取消保留重试入口，回到前台不会循环弹窗。后台返回和重新进入重新检查配置，过期回调不能解锁新会话；鸿蒙同时监听原生前台通知，避免依赖 ArkWeb 一定发出可见性事件。共享桌面统计保持现状，统计记录、上传开关和默认值不改变。

前端认证回归覆盖读取前拦截、取消重试、后台撤销、原生恢复、过期回调、开发模式重复挂载和更换宿主；Swift 回归通过注入系统上下文检查无密码、故障、锁定、取消、失败重试、后台和过期回调。系统认证窗口引起的短暂失焦与真正后台分开处理。

验证包括统计相关前端测试、HarmonyOS 逻辑测试、原生编译、quick 和笔记门禁；真实设备覆盖如实记录在 PR。鸿蒙沿用未改动的 Rust/NAPI 编译产物检查 ArkTS 与 HAP，iOS 使用原生工程验证，不能用 TypeScript 测试代替原生编译。
