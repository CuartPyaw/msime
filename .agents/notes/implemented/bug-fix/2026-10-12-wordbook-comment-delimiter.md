# Agent Note: 词书导入只用数据行判断分隔符

Status: implemented

## Problem

词书导入会跳过空行和 `#` 注释，却用全文是否含制表符决定 CSV 或 TSV。CSV 注释里的制表符会让所有有效逗号行按 TSV 解析；即使数据本身正确，导入也会返回 `NoUsableRows`。首条 CSV 数据行的引号字段也可能包含制表符；只检查该行是否含制表符仍会误判格式，把逗号和引号导入词条并丢掉后续有效行。

## Decision

从首条非空、非注释的数据行判断分隔符，随后整份文件仍只用这一种格式解析。与逐行解析共用相同的跳过规则，注释内容不影响格式。首条数据行含制表符时，只有它能按 CSV 分出多个字段、且所有制表符都在引号字段内，才视为 CSV；其余仍视为 TSV，保留 TSV 把未闭合引号当作字面文本的规则。没有制表符时视为 CSV；格式探测与实际分列共用同一个 CSV 扫描器，双引号转义和字段起始规则只维护一份。引号内首尾制表符仍按字段原有的去空白规则处理，字段内部制表符仍按控制字符拒绝该行；后续格式不符的行仍按原有行级失败规则报告。

## Alternatives considered

- 扫描所有非注释行，只要其中一行含制表符就选 TSV：能保留部分首行损坏而后续为 TSV 的文件，但一个后续损坏行里的制表符仍会改变之前有效 CSV 行的解释。
- 为格式探测另写一套引号状态机：不必构造首行字段，但与实际分列各维护一份转义和引号规则，容易再次分歧；首行至多多解析一次，复用扫描器更直接。
- 由文件扩展名指定格式：调用者知道文件名时可避免猜测，但当前 `parse` 只接收文本，改变接口和各宿主调用点超出了这个缺陷的范围。

## Consequences

带制表符的注释或 CSV 引号字段不再使 CSV 被误判为 TSV；TSV 和普通 CSV 的既有解析继续适用。若首条数据行本身损坏且误导格式判断，后续行仍可能被拒绝，这与只允许一份文件使用一种分隔符的既有约定一致。注释回归在旧实现下得到 `NoUsableRows`；引号字段回归在旧实现下写错首个词条、跳过后续有效行。验证覆盖这两种边界以及既有的跨行引号、转义双引号和 TSV 分列。改动只涉及纯文本解析，不改变文件读写或磁盘格式。
