# Agent Note: 九键单整句跳过神经重排准备

Status: rejected — 模型缺失空列表的冷/热两组控制均回退约6.56%，超过预设5%上限；生产保持基线。

## Problem

`NineKeySession::rerank_sentences` 在模型可用但没有或只有一条词网格整句时仍进入缓存签名和临时 `SentencePath` 构造。`NeuralReranker` 对少于两条路径直接拒绝评分，准备成本不能产生模型排名。此入口只用于引擎内 `neural_keyboard` 开关，默认 `rerank_latency` 的 Runtime 独立模型不经过它，因此本片不能解决默认九键 p95 超预算。

## Proposal

保留原模型加载时机和缺失模型的失败缓存。在模型可用且整句少于两条时沿用空模型排名，不创建签名、临时路径或空排名缓存条目。两条及以上整句继续使用现有评分路径。最终统一执行既有候选放置，保留词网格关闭时的移除规则。

## Historical audit

检索活跃树的 `rerank_sentences`、`scored_len`、单路径和拒绝重排。[九键重排缓存借用](../../implemented/testing/2026-10-16-nine-key-rerank-cache-borrow.md)持有命中签名比较；[九键临时路径字段](../../implemented/testing/2026-10-16-nine-key-rerank-path-payload.md)持有真实多路径评分的字段裁剪；[通用重排文本缓冲](../../implemented/testing/2026-10-09-rerank-text-buffer.md)用于 Runtime 的另一入口。三者部分重叠但不覆盖本入口的单路径准备；均保留，没有完全吸收或过时提案。

## Alternatives considered

- 保留现状：生命周期最简单，但为必然拒绝的输入创建临时签名和路径，缓存还会挤掉有有效排名的条目。
- 在模型内部处理：已有少于两条的拒绝，不能阻止入口先建立拥有对象。
- 在加载模型前拒绝：避免首次加载，但会推迟缺失模型的失败缓存并改变后续资源可见性，故撤回首版；缺失模型夹具的5次申请来自加载准备，不能当作已加载模型路径收益。

## Acceptance criteria

先在真实模型下运行旧代码的零分配红测试，不能依赖缺失模型的加载差异。冻结基线完整入口对照0/1/2/12条整句、模型可用/不可用、词网格与重复选项、上下文、相邻调用变化；比较全部候选字段与实际模型初始化状态。另覆盖混入数据库行及非整句生成行，以及超过16个不同短签名挤出旧缓存后回访原多路径输入。两条及以上评分缓存保持原字段，短列表不再插入空排名缓存，这是有意变化。

普通System分配器下完整入口配对覆盖0/1/2条整句、模型可用/不可用、冷/热缓存。模型可用的0/1条冷缓存目标新旧中位比必须小于0.98，其余控制小于1.05；每格21对交换先后，包含候选复制、入口及候选析构，校准至少5ms。无构建观测后计时，保留全部结果，失败不放宽或筛形状。另跑显式开启引擎内模型的九键质量，完整默认延迟仍保留16ms门槛。

这里的冷缓存只清空外层 `rerank_cache`；模型前缀与续算缓存保持热态，不代表首次模型推理。正确性与分配断言使用计数分配器，时间使用临时去掉全局计数分配器后复制出的 release 测试程序，构建脚本在 `finally` 逐字恢复分配器文件。

## Risks

缺失模型路径不应承担完整候选扫描；没有或一条整句的优化无法降低多个有效候选的矩阵计算成本。缓存失效和模型加载时机必须保留，不能仅用候选文本相等掩盖生命周期变化。

## Result

普通System分配器下完整入口12格、每格21对共252对样本全部保留；仅此一轮有效测量，不复跑筛选。运行4.25秒的五次观测均无构建，二进制SHA-256前后相同；这些观测不能证明机器独占。

模型可用、外层空缓存的0/1条整句新旧中位比分别为0.304570、0.342502，目标通过。但模型缺失、0条整句的热/冷缓存控制分别为1.065549、1.065635，超过事前1.05上限；旧/新每次调用耗时的各自中位数约4.89/5.22ns、4.95/5.28ns。绝对差很小，仍不能临时放宽既定验收条件。回退原因没有定位，不能据此推断模型推理退化。

原型的正确性通过：引擎库2350项、集成31项、Runtime库323项；Clippy、格式和quick门禁通过，Linux原生宿主90项测试通过。已加载真实模型的0/1条整句均为零申请，旧实现空列表红测试为1次申请。显式`--keyboard-neural --grid nine`的81例新旧完整质量报告逐字节一致，SHA-256均为`23dac8f9a06e5b6231c7c797b9c2072eac994592ae89a44394913a8c0ddc4562`，top1为0.605、MRR为0.632；不能把这个模式与默认Runtime报告混为同一次质量测量。
